# Размещение на собственном VPS

Этот сценарий подготовлен для будущего сервера. Команды на VPS пока не выполнялись. Выбор и оплату сервера/домена делаем отдельно.

## 1. Подготовка

Понадобятся Linux VPS, SSH-доступ, установленный Docker Engine с Compose и домен или поддомен. Приложение состоит из трех контейнеров: сервер Python, PostgreSQL и Caddy. База и приложение не публикуют свои порты наружу; доступны только порты 80/443 у прокси. Для практики подойдет небольшой сервер; размер выберем после выбора провайдера.

Создайте DNS-запись A для домена на IP сервера. Если используете AAAA, IPv6 также должен вести на этот VPS. Настройте доступ по SSH-ключу и разрешите входящие SSH, HTTP и HTTPS средствами провайдера или системного файрвола. Проверка доступности SSH обязательна до изменения правил.

## 2. Копирование проекта

Перенесите исходники проекта в отдельный каталог на сервере, например `/opt/svod`. Исключите `.venv`, `.local`, `work`, `__pycache__`, тестовые базы и банковские PDF. Существующий `.env` не публикуйте. `Dockerfile` копирует только серверные исходники и интерфейс.

## 3. Настройки

В каталоге проекта:

```sh
cp .env.example .env
chmod 600 .env
python3 -c "import secrets; print(secrets.token_hex(32))"
```

В `.env` запишите настоящий домен в `APP_DOMAIN` и сгенерированный пароль в `DB_PASSWORD`. Используйте hex-строку: она подходит для URL подключения к базе без дополнительного кодирования.

## 4. Запуск и первый профиль

```sh
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose run --rm app python -m backend.manage create-user
```

Последняя команда интерактивно запросит почту, имя и пароль. Пароль вводится скрыто. В production создание первого профиля через сайт отключено. Таким же способом добавляются последующие пользователи; у каждого независимые счета и документы.

Caddy получает и продлевает сертификат при корректном DNS и доступных портах 80/443. Откройте `https://ваш-домен`, войдите и загрузите документы. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

Если приложение не стало доступно:

```sh
docker compose logs --tail=100 app
docker compose logs --tail=100 proxy
```

Не отправляйте необработанные логи или `.env` в открытый доступ. Логи HTTP-запросов приложения отключены, чтобы поисковые строки операций не записывались в access log.

## 5. Проверка перед переносом основных данных

1. Открывается HTTPS без предупреждения сертификата, доступен вход.
2. Временный второй профиль не видит счета, операции и выгрузки первого.
3. Загрузка справки, подтверждение и повторная загрузка дают ожидаемый результат.
4. Перезапуск контейнера сохраняет данные.
5. Подключаются обе публичные ссылки Snowball, обновление добавляет снимок.
6. Проверена резервная копия и тестовое восстановление в отдельную базу.

Docker-конфигурация и код PostgreSQL подготовлены; эти проверки будут проведены на выбранном VPS.

## 6. Резервные копии

На сервере создайте закрытый каталог резервных копий и сделайте дамп:

```sh
mkdir -p backups
chmod 700 backups
docker compose exec -T db pg_dump -U svod -d svod -Fc > backups/svod.dump
chmod 600 backups/svod.dump
```

В дампе находятся финансовые данные всех пользователей. Храните отдельную защищенную копию вне VPS. Кроме дампа понадобится `.env` в защищенном месте и исходники соответствующей версии. Выгрузка JSON из интерфейса полезна для своих данных, но не заменяет резервную копию всей базы.

Для проверки восстановления создайте отдельную базу, не изменяя действующую:

```sh
docker compose exec -T db createdb -U svod svod_restore_check
docker compose exec -T db pg_restore -U svod -d svod_restore_check < backups/svod.dump
```

Проверьте таблицы и количество записей. Перед любым восстановлением в рабочую базу остановите запись, сделайте новую копию и отдельно проверьте целевую базу. Автоматическое удаление действующих данных не предусмотрено.

## 7. Обновления

Сначала резервная копия и проверка миграций новой версии, затем:

```sh
docker compose up -d --build
```

Не используйте `docker compose down -v`: этот флаг удаляет том базы. Для обычной остановки достаточно `docker compose stop`, для запуска — `docker compose start`.

## Установка на устройства

На Android откройте сайт по HTTPS в Chrome и воспользуйтесь пунктом установки приложения. На ПК аналогичный пункт есть в поддерживаемых браузерах Chrome/Edge. Проверим фактическое поведение после размещения. Все устройства используют одну серверную базу; локальная SQLite-база с компьютера сама на сервер не переносится. Для первой серверной загрузки проще повторно импортировать исходные справки и подключить Snowball.
