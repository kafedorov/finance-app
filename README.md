# Свод · личные финансы

Первая рабочая версия: адаптивное веб-приложение для компьютера и телефона. Поддерживает установку как PWA. Название «Свод» пока рабочее.

## Запуск на этом компьютере

Дважды щелкните `Start.cmd` в папке проекта. Также его можно запустить из терминала:

```powershell
.\Start.cmd
```

Затем откройте **http://127.0.0.1:8765**. Окно терминала должно оставаться открытым; Ctrl+C останавливает сервер. `Start.cmd` не требует разрешения на выполнение PowerShell-скриптов. Альтернативный запуск напрямую:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.asgi:app --host 127.0.0.1 --port 8765 --no-access-log
```

На первом запуске создайте свой профиль: имя, почта как логин и пароль от 6 символов. Письма приложение не отправляет. Почта и пароль хранятся в локальной базе; пароль — только в виде хеша Argon2. Демо доступно без регистрации и содержит исключительно вымышленные данные.

Исходные справки не предзагружены в ваш профиль. Откройте «Загрузки», выберите два предоставленных PDF, проверьте результаты и подтвердите каждый импорт. Во время разработки настоящие справки проверялись в отдельной тестовой базе, не в пользовательском профиле.

В «Инвестициях» подключите по очереди две публичные ссылки Snowball, выбрав брокерский счет и ИИС. Для обновления служит кнопка «Обновить», не чаще раза в минуту. Каждый успешный запрос сохраняет новый снимок. Фоновое обновление по расписанию пока не добавлено.

## Что уже работает

- Обзор капитала по последним данным рублевых счетов. Дата каждого источника указана отдельно; иностранные остатки не конвертируются автоматически.
- Расходы по дням, месяцам и категориям, поиск и фильтры операций.
- Ручная классификация и сохранение правил для точно такого же описания и направления операции.
- Отдельный учет доходов, возвратов, переводов между своими счетами и операций, требующих уточнения. Пополнения по СБП не объявляются доходом автоматически.
- История снимков остатка вклада. Проценты не выводятся из изменения остатка без истории движений.
- Публичные портфели Snowball: стоимость, прибыль, среднегодовая доходность XIRR, изменение за день и прогноз выплат. Публичный веб-запрос проверен на обеих предоставленных ссылках.
- Предварительный разбор PDF, сверка банковских итогов и подтверждение импорта.
- Защита от повторной загрузки файла и учета одинаковых операций из пересекающихся выписок с сохранением кратности совпадающих строк. Измененное время списания не создает повтор. Неоднозначные совпадения описаний блокируют импорт.
- Несколько отдельных пользователей, серверные сессии, CSRF-защита, ограничение попыток входа и проверка владельца данных.
- Выгрузка своих счетов, снимков, операций, правил и истории загрузок в JSON. Восстановление из JSON через интерфейс пока не реализовано.

## Разработка на другом компьютере

Нужен Python 3.12. Интерфейс не требует сборки или npm-зависимостей.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m uvicorn backend.asgi:app --host 127.0.0.1 --port 8765 --no-access-log
```

На Linux используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`. При изменении исходников перезапускайте сервер, а интерфейс обновляйте в браузере.

Локально используется SQLite, на VPS — PostgreSQL. Схема имеет версию 3; повторный запуск не изменяет существующую схему. Будущие изменения структуры требуют новой явной миграции. `create_all` используется только для начальной схемы. Переход 1 → 2 добавляет настройки скрытия счетов, привязку к банку и отметку просмотра операций; перед обновлением локальной SQLite автоматически создается копия в `.local/backups/`.

## Что учитывать в этой версии

- Поддержаны проверенные шаблоны Т-Банка и Яндекс Банка с текстовым слоем. OCR для сканов не добавлен.
- При неоднозначном совпадении старого и нового описания импорт останавливается; отдельный экран разрешения таких конфликтов еще нужен.
- Исходные PDF не сохраняются сервером. Остаются разобранные операции и информация о загрузке; неподтвержденный результат живет 30 минут и очищается при следующей загрузке пользователя.
- Snowball использует публичный веб-запрос с фиксированным адресом. Это не документированный API-контракт: изменение сервиса может потребовать правки адаптера. При сбое сохраняется последний успешный снимок с отметкой об ошибке.
- Установка PWA требует HTTPS либо localhost и поддерживаемого браузера. Оболочка доступна без сети, финансовые данные офлайн не кэшируются. Реальная установка на Android и Windows пока не проверялась.
- Восстановления пароля по почте, публичной регистрации, приглашений через интерфейс и отдельных APK/EXE пока нет. Дополнительные профили создает администратор через CLI.
- Проверки выполнены локально на SQLite. Docker/PostgreSQL/HTTPS на VPS еще не запускались: сервер и домен пока не выбраны.

Подробности проверок — в `VALIDATION.md`, исходные требования — в `ARCHITECTURE.md`.

## Банки, скрытые вклады и индикатор операций

Разделы называются «Карты» и «Вклады». На страницах обзора, карт, вкладов и инвестиций есть переключатель «Все банки» / конкретный загруженный банк. Он меняет счета, капитал, расходы, графики, список операций и счетчик. Варианты банков берутся из данных текущего пользователя; новый банк появляется после регистрации его адаптера и загрузки отчета. В подключении Snowball выбирается банк портфеля.

Чтобы убрать ненужный вклад, нажмите крестик на его карточке. Он исключается из активного списка и общего капитала, история остается в базе. Внизу раздела есть «Скрытые вклады» с кнопкой возврата. Повторный импорт справки не отменяет скрытие. Выгрузка JSON включает и скрытые счета.

Индикатор возле «Карт» считает только новые непросмотренные операции со статусом «Нужно уточнить». Кнопка «Сбросить счетчик» отмечает их просмотренными в выбранном банке. Она не меняет типы операций и не относит переводы к расходам/доходам. Старые операции доступны через фильтр «Нужно уточнить»; вновь импортированные неразмеченные операции увеличивают счетчик. Повторная выписка не возвращает уже просмотренные операции в индикатор.

Для нового обработчика создайте модуль в `backend/importers/`, объявите `BANK_ID`, `BANK_NAME`, `ADAPTER_VERSION`, `detect()` и `parse_pages()`, верните общую модель и зарегистрируйте модуль в `ADAPTERS` файла `registry.py`. Метаданные и идентификатор банка должны задаваться обработчиком, а не извлекаться как инструкции из документа. Сейчас действующий обработчик — `tbank.py`.

## Свои категории расходов

В окне операции выберите «Как учитывать → Расходы», затем нажмите «＋ Добавить свою категорию» под списком категорий. Введите название, например «Квартира», и сохраните. Категория останется в вашем профиле и появится в разметке, фильтрах и графиках. По умолчанию меняется только выбранная операция; массовое применение включается отдельно галочкой.

Снятие наличных можно отнести к оплате квартиры: после такой разметки сумма учитывается в расходах по этой категории. Повторная загрузка выписки сохраняет ручную разметку. Категории разных пользователей независимы; одинаковое название можно использовать в каждом профиле. Названия до 80 символов, пробелы нормализуются; повторное создание возвращает существующую категорию.

Миграция схемы 2 → 3 добавляет таблицу личных категорий. Перед ней локальная SQLite сохраняется в `.local/backups/before-v3-…`. Существующие операции не изменяются. Выгрузка JSON содержит и созданные категории, которые еще не использовались.

Для этого обновления прошли 18 тестов API и учета, включая оплату квартиры через снятие наличных, фильтрацию, повторный импорт и разделение пользователей. Синтаксис интерфейса проверен Node.js; визуальная проверка в браузере для этого обновления не проводилась.

## Яндекс Банк

Обработчик `backend/importers/yandex.py` поддерживает выписку по договору карты и справку об остатке вклада. Их можно загрузить через обычный раздел «Загрузки», проверить и подтвердить. После импорта появляется банк «Яндекс Банк» в фильтрах. Миграция базы не требуется.

Объединенная выписка, содержащая историю электронного кошелька до открытия банковского счета и историю самого счета, учитывается как одна карта со стабильным идентификатором текущего банковского счета. Итоги поступлений и списаний, а также равенство начального остатка, движений и конечного остатка проверяются отдельно в каждом разделе. Отдельная выписка только старого кошелька без реквизитов банковского счета пока не поддержана.

Перенос денег с кошелька на счет и переводы между счетами одного клиента размечаются внутренними переводами. Неоднозначные переводы и погашения основного долга требуют уточнения. Валюта покупки сохраняется отдельно от рублевого списания, включая армянские драмы из проверенного образца. Отчетный остаток карты берется на дату окончания выписки, а не на дату ее создания.

Ограничение PDF увеличено до 600 страниц для объединенной выписки на 375 страниц. Исходные документы и их текст не включены в исходники. Личные данные заголовков не сохраняются в модели импорта.

Проверка Яндекс Банка: 23 теста прошли. Оба предоставленных PDF прошли полный HTTP-цикл предварительного просмотра, подтверждения и повторной загрузки в отдельной временной базе. Проверены 6120 операций, остатки, фильтр банка и отсутствие повторов. Временная база удалена после проверки; пользовательская база при добавлении обработчика не менялась.

Дополнительно поддержана выписка по договору срочного вклада «Сейв»: проверяются движения и итоги, сохраняется остаток по вкладу. Она объединяется со справкой об остатке того же счета и не создает карту. Проверенный файл карты имеет суффикс «(2)»; без суффикса в предоставленном наборе находится выписка вклада. Прошли 24 теста.

## Накопительный счет Яндекса

Адаптер `yandex-certificates-v3` распознает отдельную выписку по договору вклада до востребования «Сейв». Накопительный счет появляется отдельной карточкой в разделе «Вклады»; на обзоре его остаток входит в «Вклады и счета» и общий капитал. Срочный вклад по-прежнему импортирует только остаток. Если ранее по тому же накопительному счету загружена справка об остатке, выписка уточняет тип уже существующего счета, сохраняя его историю и скрытие. Изменение схемы базы не требуется.

Все движения накопительного счета сохраняются. Переводы между счетами одного клиента с обеих сторон относятся к внутренним переводам: автопополнение не увеличивает расходы или доходы, а покупка учитывается по списанию с карты. Проценты относятся к доходам. Внешние переводы требуют разметки: перевод другому человеку можно отнести к расходам и выбрать свою категорию; собственные переводы в другой банк не следует относить к расходам. Приложение не удаляет операции по совпадению суммы и даты между разными счетами.

В выписке накопительного счета банк указывает только дату операции. Одинаковые строки одного дня сохраняются с учетом количества повторов; для расчетов используется дата без выдумывания времени. Проверяются суммы зачислений и списаний, период операций и равенство начального и конечного остатка. Из движений восстанавливаются остатки на конец дня; в предварительном просмотре показывается только последний остаток каждого счета. Повторный или пересекающийся импорт использует существующую защиту от повторов отдельно для каждого банковского счета.

Операции накопительного счета доступны в общем списке раздела «Карты» и в аналитике обзора. В строке показан исходный счет. Фильтр «Операции счета» меняет только список, показатели и графики выше остаются за выбранный банк и период. Накопительный счет можно скрыть и вернуть по аналогии со вкладом.

Проверки обновления: 31 тест прошел, включая оба порядка загрузки карты и накопительного счета, повторный импорт, две одинаковые операции за день, ручную разметку, отдельную справку об остатке, скрытие и разделение пользователей. Синтаксис и построение HTML интерфейса проверены; визуальная проверка в браузере не проводилась.

Настоящие PDF карты и накопительного счета прошли предварительный просмотр, подтверждение и повторную загрузку через HTTP в отдельной временной базе: 6120 операций карты и 3324 операции накопительного счета, 783 дневных остатка. Добавление накопительного счета не изменило сумму расходов по карте; повторный экспорт пропустил все 3324 уже учтенные операции. Пользовательская база не менялась.

## Входящие переводы от людей

Входящий СБП-перевод с именем отправителя, как в выписке Яндекса, автоматически учитывается как доход в категории «Переводы от людей». Переводы между своими счетами, возвраты и явные ручные правила сохраняют свой приоритет. Телефон отправителя, который пользователь ранее отметил своим переводом, распознается при поступлении из другого банка; такие суммы не увеличивают доход. Одного совпадения имени недостаточно, чтобы признать перевод своим. Эта информация берется только из разметки текущего профиля.

Пополнения Т-Банка без отправителя, входящие с неизвестной карты и внесение наличных остаются на ручную разметку. Правило не относит к доходам все положительные операции подряд.

Обновление применено к ранее неразмеченной истории текущего профиля за все месяцы. Будущие загрузки используют те же правила; повторный импорт сохраняет категории и количество операций.

## Уточнение правил Т-Банка для новых загрузок

Новые входящие «Пополнение. Система быстрых платежей», «Пополнение через СБП. …» и «Перевод по СБП» всегда начинают со статуса «Нужно уточнить». Ранее сохраненные общие правила для этих анонимных описаний при импорте игнорируются. Каждое такое поступление размечается отдельно; флажок применения ко всем похожим операциям для него убран. Сервер также обрабатывает запрос старой версии интерфейса с таким флажком как изменение только одной выбранной операции.

Входящие «Перевод с договора …» и «Внутрибанковский перевод с договора …» по умолчанию относятся к доходам, даже если отправитель не указан. Правило относится только к положительным операциям Т-Банка. Явные правила для конкретных собственных переводов сохраняют приоритет.

Это изменение применяется к новым операциям при загрузке выписок. Уже сохраненная история и ее категории не переразмечаются, в том числе при повторной загрузке пересекающейся выписки.

## Обновление интерфейса для ПК и аналитики

В разделе «Аналитика» доступны динамика до трех категорий, группировка по месяцам/неделям/дням, таблица «категории × месяцы», причины изменения расходов, сравнение темпа расходов внутри месяца, доходы и расходы, а также начисленные проценты по накоплениям. В истории категорий показывается до 24 месяцев. Показатели вверху относятся к выбранному периоду; график по месяцам также показывает предшествующую историю.

Фильтры периода, банка и счета общие для обзора, показателей, графиков и операций. Доступны месяц, квартал, год, произвольные даты и все время. Нажатие точки графика или ячейки таблицы открывает соответствующие расходы. Кнопка «Вернуться к графику» восстанавливает предыдущий период и выбранные категории. Список операций сохраняет загрузку страницами по 40 строк.

Графики используют собственную быструю подсказку вместо браузерного прямоугольника. Наведение выбирает ближайшую дату, стрелки на клавиатуре перемещают выделение, Enter открывает операции, Escape закрывает подсказку. Подсказка общая для страницы, ее движение не вызывает сетевых запросов за данными и не перестраивает приложение. Для длинных историй линия прореживается с сохранением экстремумов; подробные значения остаются доступны при наведении.

Аналитика суммирует рублевые операции в базе. Переводы между своими счетами не входят в расходы и доходы, возвраты показаны отдельно, неразмеченные списания вынесены в отдельный показатель. Для неполного месяца сравниваются одинаковые части месяцев. Полнота выписок проверяется отдельно по каждому счету: пропуски отмечаются как отсутствие данных, при неполном покрытии надежное процентное сравнение не показывается. Устаревшая выписка одного банка не скрывает новые операции другого. Для справок только об остатке история движения и начисленных процентов не выдумывается.

Пользовательская база при обновлении не меняется; схема остается версии 3. Старые выписки повторно загружать не требуется. После замены файлов нужно перезапустить `Start.cmd` и обновить страницу.

Проверки: 56 тестов учета/API/аналитики и 4 браузерных сценария Chrome. Проверены быстрые подсказки, управление с клавиатуры, выбор категорий, переходы к операциям и обратно, фильтры, отсутствие запросов к API при наведении и длинные истории. На локальной истории из 11 687 операций медианное время расчета аналитики составило около 51 мс, ответ — около 25 КБ. В Chrome отрисовка графика из 10 000 точек заняла примерно 35–60 мс и использовала 18 SVG-элементов. Это локальные измерения, не гарантия времени на любом компьютере.

Для разработки и браузерных проверок после установки Node.js:

```powershell
npm install
npm run check
npm run test:ui
```

Playwright используется только для тестов, в браузер пользователя эта библиотека не загружается. Тесты запускают отдельный сервер на порту 8791 с временной базой и используют установленный Chrome. Можно указать `SVOD_BROWSER=msedge` для Edge или `SVOD_PYTHON` для другого пути к Python. Основное приложение по-прежнему запускается через `Start.cmd` без Node.js.

## Git и возврат к предыдущей версии

Репозиторий локальный, внешнего сервера Git нет. Ветка `main` и метка `before-desktop-refresh` содержат рабочую версию до обновления. Новое оформление и аналитика находятся в `feature/desktop-analytics`.

Для переключения версии остановите приложение, убедитесь в отсутствии несохраненных изменений командой `git status`, затем:

```powershell
git switch main
# Запустите Start.cmd — откроется предыдущая версия.

git switch feature/desktop-analytics
# Запустите Start.cmd — вернетесь к обновленной версии.
```

Git сохраняет код и документацию; личная база, выписки, пароли и окружение исключены. Переключение версии кода не откатывает разметку операций. Перед установкой обновления отдельно сохранена резервная копия SQLite в `.local/backups/` с префиксом `before-desktop-refresh-`.
